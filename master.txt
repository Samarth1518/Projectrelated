status algorithm is deliberately simple and based on the observed PDF
behavior: 1. Read each extracted line. 2. If a STEP ID appears at the
start of the line, save it as current_step_id. 3. If the line contains
Success or Failure, use the saved current_step_id. 4. Add that STEP ID
to the corresponding lowercase status list. 5. Clear current_step_id. 6.
Continue until the procedure block ends. The strict STEP-ID rule is
important because time values can also contain numbers and punctuation.
The parser does not search for a STEP ID anywhere in the line. 15.

Short explanation: Our project takes a structured PDF as input and
extracts the required process information. PyMuPDF is used to open the
PDF and extract its text. Python regular expressions identify Procedure,
Time, Duration, STEP IDs, and their status. The extracted information is
organized into Python dictionaries and written as structured JSON in
output.json. Fields that are not required, such as Mode, Source,
Priority, STEP description, and table TIME, are ignored. Why PyMuPDF? It
is used to open the PDF and extract its text so Python can process the
required information. Why regular expressions? They identify known text
patterns such as Procedure, Time, Dur, STEP IDs, and status values. Why
JSON? JSON provides a structured, machine-readable representation of the
extracted information. Why two Python files? main.py controls the
workflow, while pdf_parser.py contains extraction logic. This keeps the
code organized and maintainable. Why no AI? The PDF has a known
structure, so deterministic parsing is sufficient and predictable. Why
are STEP IDs strings? They are identifiers, not mathematical values.
Strings preserve leading zeros such as 01.0001. 24. COMMON INSTRUCTOR
QUESTIONS Can it handle a 6,479-page PDF? Yes. The tested college PDF
itself contains 6,479 pages and was processed successfully. Can it
handle any PDF? No. It is designed for compatible structured PDFs. A
