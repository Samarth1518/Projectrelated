5. WHEN YOU GET A NEW PDF — EXACT STEPS Important: The current program
processes one PDF at a time and opens input/input.pdf. 1. Keep a backup
of the current working project. 2. Get the new PDF. 3. Open the project
input folder. 4. Make the PDF you want to process the file named
input.pdf. 5. Other PDFs may stay there with different names, but
main.py only reads input.pdf. 6. Do not change main.py just because the
PDF is new, if it follows the same supported structure. 7. Run main.py
in PyCharm. 8. Wait for processing to finish. 9. Check the console
counts. 10. Open output.json and inspect it. 11. If you want to preserve
the result, copy/rename output.json before another run because the next
run overwrites it. Example: input/ ■■■ old_college_pdf.pdf ■■■
test_pdf.pdf ■■■ input.pdf ← current PDF Typical console output: Total
pages: 6479 Total text length: 11334398 Total procedures: 1254 Total
dictionaries created: 1254 No. of Pages read: 6479 JSON file created
successfully. 6. BACKUP / SAFE WORKING RULES Known-good version: Before
a new experiment or code change, keep a copy of the current project.
Make changes in the working copy, run the program, check the console and
output.json, and keep the update only if it works. If it fails, return
to the known-good backup. Also preserve important test PDFs and
successful JSON outputs separately. 7. IF A NEW STATUS IS FOUND — EXACT
CODE-CHANGE PROCESS If the actual college PDF contains Progress,
Suspend, or another status, change only the status pattern in
pdf_parser.py. Step 1: Open pdf_parser.py. Step 2: Find: status_match =
re.search( r”Success|Failure), line, re.IGNORECASE ) Step 3: For
Progress and Suspend, change it to: status_match = re.search(
r”Success|Progress|Suspend|Failure), line, re.IGNORECASE ) Step 4: Save
pdf_parser.py. Step 5: Run main.py with the PDF as input/input.pdf. Step
6: Check output.json. The new status automatically becomes its own
lowercase key with its STEP IDs. “status”: { “success”: [“01.0001”],
“progress”: [“01.0002”], “suspend”: [“01.0003”],

NEW PDFS / NEW REQUIREMENTS Same structure, new PDF: Replace input.pdf
and run; usually no code change. New status: Update the status regex in
pdf_parser.py. Different metadata layout: Inspect extracted text first,
then modify the relevant parser rule. Different STEP ID format: Modify
the STEP-ID regex only if the actual PDF requires it. New JSON field:
Add extraction logic in the parser and then add the field to
process_data in main.py. Multiple PDFs automatically: New requirement;
current project is one active input.pdf at a time. Very large PDF: No
fixed page-count rule, but larger PDFs can take more time and memory
because all extracted text is stored in all_text. Different overall
structure: Do not assume compatibility; inspect the PDF text before
changing code. 9. PROJECT REMINDERS  Non-AI: normal Python + PyMuPDF +
regex + JSON.  Working environment: Python 3.6.5 and PyMuPDF 1.18.18. 
Text extraction, not OCR.  Designed for the known process/table PDF
structure.  STEP IDs such as 01.0001 remain strings.  Mode, Source,
Priority, and table TIME are intentionally ignored. Use this as the
college reference. When a real new PDF or requirement arrives, inspect
it first and make the smallest necessary change.
